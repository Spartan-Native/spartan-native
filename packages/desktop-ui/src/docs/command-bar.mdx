# Command bar

`<sn-command-bar>` is the command surface of a window or page: a title, the primary commands for the current
view, and an overflow menu for secondary commands. You write it once; it is laid out as the command surface of
the current OS. Use it at the top of a content view whose commands act on that view (New, Share, Delete over a
file list). For app-wide menus use a menu bar; for commands on one item use a context menu.

| OS | Renders as | Layout |
| --- | --- | --- |
| Windows 11 | **CommandBar** (native) | Title left, commands right, icon + label beside, `…` overflow |
| Windows 10 | UWP CommandBar | As Windows 11, labels under the icons, square buttons |
| macOS 26 | Unified NSToolbar | Bold title left, icon-only commands in one Liquid Glass capsule, `…` overflow |
| macOS 13–15 | Unified NSToolbar | Bold title left, icon-only toolbar buttons with a hover bezel |
| GNOME | AdwHeaderBar | Icon-only flat buttons at the start, bold title centered, menu button (☰) at the end |
| KDE Plasma | KToolBar | Title, separator, tool buttons with text beside the icon, ☰ at the end; Breeze accent frame on hover |
| ChromeOS | M3 top app bar (small) | Large title left, round icon buttons right, `⋮` overflow |

On icon-only skins the label stays as the button's accessible name and shows as the skin's own tooltip.

The title is a heading (level 1 by default) and sits where the skin puts it: centered on GNOME, at the start
elsewhere. `titlePosition="center"` centers it on every skin (a Finder-style header); a centered title stays
centered while both sides fit, and moves aside instead of running under the commands.

## Groups, priorities and overflow

`<sn-command-group>` keeps related commands together: each group is its own Liquid Glass capsule on macOS 26,
groups are divided by a separator on Windows, GNOME and KDE, and spaced on ChromeOS. `variant="accent"` marks the
view's main action.

When the bar is too narrow it first drops the labels (Windows, KDE), then moves commands into the overflow menu,
lowest `priority` first. `secondary` commands always live there, and `overflowItems` adds more entries after them.
Commands a page declares go through `[commands]`: they behave exactly like projected ones.

## API

### `sn-command-bar` inputs

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `string` | `''` | Title of the view, as a heading. Also the toolbar's accessible name. |
| `titlePosition` | `'auto' \| 'start' \| 'center'` | `'auto'` | `auto`: the skin's place (centered on GNOME). |
| `headingLevel` | `number` | `1` | The title's `aria-level`; `0` makes it plain text. |
| `commands` | `TemplateRef \| null` | `null` | Commands declared elsewhere (e.g. by the current page), rendered after the projected ones. |
| `overflowItems` | `SnMenuItem[]` | `[]` | More entries for the overflow menu. |
| `collapse` | `'auto' \| 'none'` | `'auto'` | `none`: never drop labels or collapse commands. |
| `ariaLabel` | `string` | `''` | Accessible name of the toolbar when it should differ from `title`. |
| `overflowLabel` | `string` | `'More options'` | Accessible name and tooltip of the overflow button. |

No outputs: each command is a plain `<button>`, listen to its `(click)`.

### `button[snCommand]` inputs

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | required | The command's text. Visible on Windows and KDE; accessible name and tooltip elsewhere. |
| `icon` | `string` | `''` | An `@ng-icons` name the app registered with `provideIcons()`. Or project your own `<svg>` / `<ng-icon>`. Without any icon the label always shows. |
| `disabled` | `boolean` | `false` | Disables the command; arrow keys skip it. |
| `hideLabel` | `boolean` | `false` | Icon-only on every OS (like an AppBarButton with a collapsed label). |
| `variant` | `'default' \| 'accent'` | `'default'` | `accent`: filled with the accent color, for the view's main action. |
| `priority` | `number` | `0` | Lower priorities move into the overflow menu first when the bar is too narrow. |
| `secondary` | `boolean` | `false` | Always in the overflow menu (WinUI secondary commands). |

### `sn-command-group` inputs

| Name | Type | Default | Description |
| --- | --- | --- | --- |
| `label` | `string` | `''` | Accessible name of the group (`role="group"`). |

### Content slots

| Selector | Where it goes |
| --- | --- |
| `button[snCommand]` (default slot) | The primary commands, inside the toolbar. |
| `sn-command-group` (default slot) | A group of commands; nest `button[snCommand]` inside. |
| `ng-template[snCommandOverflow]` | Your own overflow menu (an `hlmDropdownMenu` or any `cdkMenu`). Used while the bar has nothing of its own for the menu; once commands collapse (or with `secondary` commands or `overflowItems`) the bar draws the menu itself. |
| `[snCommandBarStart]` | Before the title, outside the toolbar: back button, sidebar toggle, macOS window controls. |
| `[snCommandBarEnd]` | After the commands, outside the toolbar: search field, GNOME window controls. |

### CSS hooks

| Hook | On | Values |
| --- | --- | --- |
| `data-slot` | host, each command | `sn-command-bar`, `sn-command` |
| `data-family` | host | `windows`, `macos`, `linux`, `chromeos`, `web` |
| `data-skin` | host | `win`, `w10`, `mac`, `macc`, `gtk`, `qt`, `cros`, `web` |
| `data-icon-only` | command | present when the label is hidden |
| `data-variant` | command | `accent` |
| `data-collapsed` | command | present while it is in the overflow menu |
| `data-compact` | host | present when the bar dropped the labels to make room |
| `data-title` | host | `start`, `center` |
| `.sn-chrome` | host | the theme dims the bar when the window is inactive |

## Accessibility

- The commands and the overflow button form one `role="toolbar"`, named by `title` (or `ariaLabel`).
- Roving tabindex: Tab enters the toolbar once, on the last focused command (or the first enabled one).
- ← → move between commands and wrap; Home and End jump to the first and last. Disabled commands are skipped. The arrow direction follows RTL.
- The overflow button has `aria-haspopup="menu"` and `aria-expanded`. Enter, Space or ↓ open the menu and focus its first item, ↑ its last; Esc closes it and returns focus to the button.
- Icon-only commands keep their label as visually hidden text, so screen readers announce it, and show it as the skin's tooltip.
- The title is a heading (`role="heading"`, `aria-level` from `headingLevel`).
- Collapsed commands leave the toolbar (and the arrow-key order) and appear as items of the overflow menu.
