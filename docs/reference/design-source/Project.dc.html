Host adapters

One contract. Five adapters.

Every adapter implements the same NativeHost interface and shares the same types. What differs is how much each runtime can do natively; components check capability flags and fall back gracefully. Support levels are planned and will be confirmed in the adapter spike.

Shared contract · @spartan-native/theme
// Implemented by every adapter, consumed by every component.
export interface NativeHost {
  readonly runtime: 'web' | 'wails' | 'tauri' | 'electron' | 'dotnet';
  readonly capabilities: HostCapabilities;
  platform(): Promise<PlatformInfo>;         // OS, version, desktop → skin
  appearance(): Promise<AppearanceState>;
  onAppearanceChange(cb: (s: AppearanceState) => void): Unsubscribe;
  readonly window: WindowHost;          // focus, effects, title bar
  readonly menus?: MenuHost;            // native app & context menus
  readonly notifications?: NotificationHost;
}

export interface AppearanceState {
  skin: Skin;                           // from PlatformInfo, user can override
  accent: string;                       // #rrggbb
  scheme: 'light' | 'dark';
  contrast: 'normal' | 'more' | 'forced';
  reduceTransparency: boolean;
  reduceMotion: boolean;
  textScale: number;                    // 1 = 100 %
}

export type Skin = 'win' | 'w10' | 'mac' | 'macc' | 'gtk' | 'qt' | 'cros' | 'web';

export interface PlatformInfo {
  os: 'windows' | 'macos' | 'linux' | 'chromeos' | 'unknown';
  version: string | null;               // '10.0.22631', '26.1', '15.6' …
  build: number | null;                 // Windows: ≥ 22000 means Windows 11
  desktop: 'gnome' | 'kde' | 'cinnamon' | 'xfce' | 'other' | null;
  skin: Skin;                           // resolved via the fallback table
  confidence: 'exact' | 'hint' | 'unknown';
}

export type HostCapabilities = Record<Capability, 'native' | 'partial' | 'none'>;

Roadmap

From mockups to packages.

Where the project is now and what comes next.

01Now
Design mockups
28 components, 6 OS patterns and a sample app across Windows, macOS, GNOME and KDE, all interactive.
02Next
Token contract & spike
Freeze the variable names and host interface; prove five stock helm components can be restyled from CSS alone.
03Next
Theme + helm packages
Accent derivation, platform variable sets, per-OS component skins, states and native behaviors.
04Later
Host adapters
Web/PWA from day one, then Electron → Tauri → Wails → Photino.NET, all passing the same conformance tests.
05Later
Desktop UI & integration
Title bars, OS patterns, native menus, window effects and Snap Layouts through the bridge.
06Later
Gaps & tooling
Tree view, number box, split button, status bar; the Claude Code plugin and a docs playground.
